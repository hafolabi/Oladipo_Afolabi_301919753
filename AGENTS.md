# Project preferences

The owner is a frontend engineer who is new to backend development. This is a database course portfolio, so code should be easy to read, run, and explain.

- Prefer clear, junior-level JavaScript and SQL. Use descriptive names and straightforward steps.
- Give related queries names such as `queries.history` rather than relying on array positions.
- Use small functions when they make a task easier to follow. Avoid unnecessary classes, frameworks, and layers of helpers.
- Split long expressions into named steps. A little repetition is fine when it makes the example easier to understand.
- Write short, natural comments explaining the purpose of a step or an unfamiliar database concept.
- Keep the database concepts required by the assignment. Explain them in plain language rather than removing correctness checks.
- Keep sample queries easy to find. Explain data-generation, measurement, and reporting helpers separately in the reading guide.
- Keep examples and documentation consistent with the actual code and saved test results.
- Keep AI-use notes brief and specific about the help given, rather than listing every assistant action by date.

Apply this style to future portfolio work as well as edits to existing files.
